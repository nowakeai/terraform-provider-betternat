# v0.2.2

## AWS Egress Identity And Bootstrap Safety

This provider patch imports BetterNAT v0.2.2 and exposes its AWS gateway
replacement-safety changes through the Terraform Registry distribution.

## What Changed

- Added `eip_allocation_ids`, keyed by availability zone, for externally
  managed EIPs that BetterNAT never releases.
- Added `retain_managed_eips_on_destroy` for safe migration of existing
  provider-managed EIPs and same-name gateway recreation.
- Added bounded retries while AWS releases a deleted launch-template name.
- Changed `primary_interface` and `snat_interface` defaults to `auto`, with
  bootstrap detection from the IPv4 default route and explicit overrides still
  available.
- Added validation for external EIP availability-zone mappings and duplicate
  allocation IDs.

## Recommended Migration

For an existing provider-managed gateway, set
`retain_managed_eips_on_destroy = true` and apply before replacement. Import the
retained allocation into an independent `aws_eip`, pass it through
`eip_allocation_ids`, and then perform the planned gateway replacement.

New production deployments should manage public identities as independent
`aws_eip` resources, normally protected by `prevent_destroy`.

## Compatibility

- Existing v0.2.x configurations remain valid.
- Existing provider-managed EIPs are still released on destroy unless
  retention is explicitly enabled.
- Supported runtime artifact versions remain `v0.2.0` and `v0.2.1`; provider
  package version and runtime version are independent.
